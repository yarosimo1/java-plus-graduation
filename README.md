# Explore With Me

**Explore With Me** — микросервисное приложение для публикации и поиска событий. Пользователи могут создавать мероприятия, подавать заявки на участие, комментировать события, просматривать подборки, а также получать статистику просмотров.

Проект реализован на основе **Spring Boot** и построен с использованием микросервисной архитектуры. Все сервисы взаимодействуют друг с другом через REST API, используя **Spring Cloud OpenFeign**, **Eureka Discovery** и **Spring Cloud Gateway**.

# Архитектура проекта

Проект разделён на три логические группы модулей.

```
explore-with-me
│
├── core
│   ├── event-service
│   ├── request-service
│   ├── user-service
│   └── interactionapi
│
├── infra
│   ├── gateway-server
│   ├── config-server
│   └── discovery-server
│
└── stats-service
    ├── stats-client
    ├── stats-dto
    └── stats-server
```

Все сервисы являются независимыми приложениями Spring Boot.

Внешние клиенты работают только с **gateway-server**.

Прямое обращение к внутренним сервисам не предполагается.

# Структура проекта

## Core

### event-service

Основной доменный сервис проекта.

Отвечает за:

- создание событий;
- изменение событий;
- публикацию событий;
- поиск событий;
- просмотр публичных событий;
- управление категориями;
- управление подборками событий;
- управление комментариями;
- взаимодействие со статистикой просмотров;
- взаимодействие с сервисом заявок.

---

### request-service

Сервис управления заявками пользователей.

Предоставляет возможность:

- создать заявку;
- отменить заявку;
- получить список заявок пользователя;
- получить заявки события;
- подтвердить заявки;
- отклонить заявки;
- получить количество подтвержденных участников события.

---

### user-service

Сервис управления пользователями.

Отвечает за:

- создание пользователей;
- удаление пользователей;
- поиск пользователей;
- предоставление информации другим сервисам через внутренний API.

---

### interactionapi

Общий библиотечный модуль.

Используется всеми сервисами проекта.

Содержит:

- DTO;
- Response модели;
- Request модели;
- Enum;
- Exception;
- Global Exception Handler;
- Validation;
- общие утилиты.

Модуль не запускается самостоятельно.

# Infrastructure

## gateway-server

Единая точка входа в систему.

Все запросы пользователей проходят через Gateway.

Основные задачи:

- маршрутизация запросов;
- балансировка нагрузки;
- интеграция с Eureka;
- скрытие внутренних сервисов;
- единая точка доступа ко всем API.

Порт:

```
8080
```

---

## discovery-server

Eureka Server.

Используется для регистрации всех микросервисов.

Каждый сервис после запуска автоматически регистрируется в Eureka.

Это позволяет сервисам обращаться друг к другу по имени приложения вместо IP-адресов.

Порт:

```
8761
```

---

## config-server

Spring Cloud Config Server.

Хранит централизованные конфигурации всех сервисов проекта.

Конфигурационные файлы расположены по пути:

```
infra/config-server/src/main/resources/config/
```

Каждый сервис получает свои настройки автоматически при запуске.

Порт:

```
8888
```

# Маршрутизация Gateway

Все внешние запросы к системе проходят через **gateway-server** (`http://localhost:8080`).

Gateway маршрутизирует запросы к соответствующим микросервисам с использованием Eureka Discovery.

| Внешний путь | Целевой сервис | Назначение |
|--------------|----------------|------------|
| `/admin/users/**` | `user-service` | Администрирование пользователей |
| `/users/*/requests/**` | `request-service` | Работа с заявками пользователя |
| `/events/**` | `event-service` | Публичный API событий |
| `/users/*/events/**` | `event-service` | Личный кабинет пользователя |
| `/users/*/comments/**` | `event-service` | Управление комментариями пользователя |
| `/admin/events/**` | `event-service` | Администрирование событий |
| `/categories/**` | `event-service` | Получение категорий |
| `/compilations/**` | `event-service` | Получение подборок |
| `/comments/**` | `event-service` | Работа с комментариями |
| `/admin/categories/**` | `event-service` | Управление категориями |
| `/admin/compilations/**` | `event-service` | Управление подборками |
| `/admin/comments/**` | `event-service` | Администрирование комментариев |
| `/hit` | `stats-server` | Сохранение просмотра |
| `/stats` | `stats-server` | Получение статистики |

# Взаимодействие микросервисов

Каждый сервис является полностью независимым приложением.

Для взаимодействия между сервисами используются:

- Spring Cloud OpenFeign;
- Eureka Discovery;
- REST API;
- Spring Cloud Gateway.

Внутренние обращения выполняются по имени приложения, зарегистрированного в Eureka.

Например:

```text
lb://event-service
lb://request-service
lb://user-service
lb://stats-server
```

Прямой доступ к базе данных другого сервиса запрещён.

Каждый сервис взаимодействует только через внутренний HTTP API.

---

# Внутренние REST API

Для обмена данными между сервисами используются внутренние эндпоинты с префиксом

```
/internal/**
```

Данный API недоступен внешним клиентам и используется исключительно микросервисами.

---

## user-service

Предоставляет информацию о пользователях.

### Получение пользователя

```
GET /internal/users/{userId}
```

Используется для проверки существования пользователя.

---

### Получение списка пользователей

```
GET /internal/users?ids=1,2,3
```

Позволяет избежать большого количества запросов (N+1).

---

### Проверка существования пользователя

```
HEAD /internal/users/{userId}
```

Возвращает только HTTP статус.

---

## event-service

Предоставляет внутренний API для остальных сервисов.

### Получение события

```
GET /internal/events/{eventId}
```

Используется сервисом заявок и другими внутренними сервисами.

---

### Получение нескольких событий

```
GET /internal/events?ids=1,2,3
```

Используется при пакетной загрузке данных.

---

### Проверка существования события

```
HEAD /internal/events/{eventId}
```

---

### Обновление количества подтвержденных участников

```
PATCH /internal/events/{eventId}/confirmed-requests
```

Используется сервисом заявок после подтверждения или отклонения заявок.

---

## request-service

Предоставляет информацию о заявках.

### Получение заявок события

```
GET /internal/events/{eventId}/requests
```

---

### Получение списка заявок

```
GET /internal/events/{eventId}/requests?ids=1,2,3
```

---

### Получение количества подтвержденных заявок

```
GET /internal/events/{eventId}/requests/count?status=CONFIRMED
```

---

### Массовое обновление статусов заявок

```
PATCH /internal/requests/status
```

Используется сервисом событий.

# Основные принципы архитектуры

Проект построен в соответствии с принципами микросервисной архитектуры.

Каждый сервис:

- имеет собственную базу данных;
- самостоятельно разворачивается;
- независимо масштабируется;
- взаимодействует с другими сервисами только по HTTP;
- не имеет прямого доступа к данным других сервисов.

Все сервисы зарегистрированы в Eureka.

Конфигурации централизованно хранятся в Config Server.

Внешний клиент взаимодействует исключительно с Gateway.

# Структура баз данных

Каждый микросервис использует собственную базу данных и полностью владеет своей схемой.

Другие сервисы не имеют прямого доступа к таблицам.

Взаимодействие между сервисами осуществляется только через REST API.

# user-service

Сервис хранения пользователей.

## Таблица `users`

| Поле | Тип | Описание |
|------|-----|----------|
| id | BIGINT | Идентификатор пользователя |
| email | VARCHAR(254) | Email пользователя |
| name | VARCHAR(250) | Имя пользователя |

### Ограничения

- `email` — уникальный.

### Индексы

- `idx_users_email`

---

# request-service

Сервис хранения пользовательских заявок.

## Таблица `user_requests`

| Поле | Тип | Описание |
|------|-----|----------|
| id | BIGINT | Идентификатор заявки |
| created | TIMESTAMP | Дата создания |
| event_id | BIGINT | Идентификатор события |
| requester_id | BIGINT | Идентификатор пользователя |
| status | VARCHAR(20) | Статус заявки |

### Возможные статусы

- `PENDING`
- `CONFIRMED`
- `REJECTED`
- `CANCELED`

### Ограничения

Один пользователь может иметь только одну заявку на одно событие.

```
UNIQUE (event_id, requester_id)
```

### Индексы

- `idx_user_requests_event_id`
- `idx_user_requests_requester_id`
- `idx_user_requests_event_status`

---

# event-service

Данный сервис хранит основную бизнес-информацию приложения.

## Таблица `events`

Основная таблица событий.

| Поле | Тип | Описание |
|------|-----|----------|
| id | BIGINT | Идентификатор события |
| title | VARCHAR(120) | Название |
| annotation | VARCHAR(2000) | Краткое описание |
| description | VARCHAR(7000) | Полное описание |
| initiator_id | BIGINT | Идентификатор автора |
| initiator_name | VARCHAR(250) | Имя автора (денормализовано) |
| category_id | BIGINT | Категория |
| category_name | VARCHAR(50) | Название категории (денормализовано) |
| paid | BOOLEAN | Платное событие |
| participant_limit | INTEGER | Лимит участников |
| request_moderation | BOOLEAN | Требуется ли модерация заявок |
| created_on | TIMESTAMP | Дата создания |
| event_date | TIMESTAMP | Дата проведения |
| published_on | TIMESTAMP | Дата публикации |
| state | VARCHAR(20) | Статус события |
| lat | REAL | Широта |
| lon | REAL | Долгота |
| confirmed_requests | INTEGER | Количество подтверждённых заявок |
| views | BIGINT | Количество просмотров |

### Возможные состояния события

- `PENDING`
- `PUBLISHED`
- `CANCELED`

### Индексы

- `idx_events_category_id`
- `idx_events_initiator_id`
- `idx_events_event_date`
- `idx_events_state`
- `idx_events_paid`

---

## Таблица `categories`

Хранит категории событий.

| Поле | Тип |
|------|-----|
| id | BIGINT |
| name | VARCHAR(50) |

Название категории является уникальным.

---

## Таблица `compilations`

Хранит подборки событий.

| Поле | Тип |
|------|-----|
| id | BIGINT |
| pinned | BOOLEAN |
| title | VARCHAR(50) |

Название подборки является уникальным.

---

## Таблица `compilation_events`

Связующая таблица между событиями и подборками.

| Поле | Тип |
|------|-----|
| compilation_id | BIGINT |
| event_id | BIGINT |

Используется связь **Many-to-Many**.

При удалении подборки записи автоматически удаляются благодаря `ON DELETE CASCADE`.

---

## Таблица `comments`

Хранит комментарии пользователей.

| Поле | Тип |
|------|-----|
| id | BIGINT |
| text | VARCHAR(255) |
| author_id | BIGINT |
| event_id | BIGINT |
| created | TIMESTAMP |
| edited | TIMESTAMP |

### Индексы

- `idx_comments_author_id`
- `idx_comments_event_id`

---

## Таблица `comment_likes`

Хранит информацию о лайках комментариев.

| Поле | Тип |
|------|-----|
| id | BIGINT |
| user_id | BIGINT |
| comment_id | BIGINT |

### Ограничения

Один пользователь может поставить только один лайк одному комментарию.

```

```

При удалении комментария все лайки автоматически удаляются благодаря `ON DELETE CASCADE`.

### Индексы

- `idx_comment_likes_comment_id`
- `idx_comment_likes_user_id`
